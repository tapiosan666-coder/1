# FIND YOURSELF v27｜B館ES・EV配置の正常化／ES裏面化粧／C館ドッグラン再設計

## 制作基準・最重要方針
- **v26の完全Godotプロジェクトを唯一の改修基準**にする。v17等の旧版へ戻さない。
- 目的は設備数を増やすことではない。**旧・新設備の不自然な共存を解消し、実際に歩いて見たときの建築的違和感をなくすこと**。
- 今回の優先順位は **①B館のES/EV整理と新連続ESの反映 ②ESの下面・側面仕上げ ③C館ドッグランを芝生と一体化 ④回帰検証**。他の内装追加で作業を分散しないこと。
- 添付の参考資料PDF、配置イメージ図、参考サイト一覧を先に確認する。模式図は**設計意図の説明であり、v26の実測図面・既存座標ではない**。実際の数値・改修範囲はソースとGodot実画面から確定する。

## 1｜現況調査：B館の昇降設備台帳を作る
通常起動の `main.tscn` と比較版 `ES_site_proposal_v15.tscn`、`Integrated_candidate_v22.tscn`、`main.gd` の切替条件、`source/site-manifest-v7.json`、`source/v15/ES-site-proposal.json`、`source/v22/integrated-ABC.json`、`source/v22/A-continuous-ES.json`、`escalator_v2.gd` を照合する。

- B館の**全階（B1、1F、2F、3F、RF）**について、旧ES・新ES・EV・階段のID、座標、向き、利用階、ワールド座標、表示条件、物理判定、床開口、上り/下り、動線を表で整理する。
- 旧ESを新連続ESに置き換えた区域と、**離れた場所にある独立ESとして残すべき区域**を区別する。無条件に旧ESを全撤去しない。
- F6の「通常統合候補／過去比較案」を切り替えたときの見た目を各階で撮る。表示メッシュだけでなくCollider、踏段移動データ、乗降ロジックも同じ採用案に統一する。
- EVとESが同じ広場・同じ動線で競合している部分を、平面図と3D俯瞰で特定。設備本体の重なり、乗り場の交錯、吹抜け開口の二重施工、梁・柱への突入を洗い出す。
- B館の新連続ES（v15/B-WEST系統）が**通常起動で実際に1F→2F→3F→RFまで見え、歩いて利用できる**ことを厳密に確認。シーンフラグやJSONに存在するだけで合格としない。
- 同じ機能を果たす旧ESが新設ESに重なっていれば退役させる。一方で必要な別系統の階移動を残す。削除理由と代替ルートを記録。

## 2｜B館の新連続エスカレーターを建築的に完成させる
- 各階の上り・下りを対で分かりやすく配置し、降りてから次の上りへ自然に乗り継げる構造にする。
- EVホールを独立した空間として整理する。ESの出口、EVの待機列、主通路、テナント入口が衝突しない。
- 乗降口付近の空きスペース、周囲の手すり、ガラス柵、床開口、見切り、階段や吹抜けへの転落防止を実画面とコリジョン双方で検査する。
- エスカレーターの乗降口、水平踏段、くし板、デッキ、側面、外装の材料を作り分ける。構造が途中で切れたり、床から浮いたりしない。
- 不自然に並立する旧設備は適切に撤去または移設し、撤去跡の床・天井・手すり・案内板・衝突判定も修復する。**旧機が消えても透明な衝突壁が残る状態を禁止**。

## 3｜ES裏側のむき出し解消【重要】
現状、下階から見上げるとエスカレーターの機械的な裏面・フレームが露出して見える。単純な箱で覆って終わりにしない。

- 本体の傾斜とランディングに沿った**連続する下面化粧パネル（soffit / underside cladding）**を設計する。
- 下から見える底面、左右側面、端部、フロアとの接続部まで仕上げる。トラス内の戻り踏段や機械が、通常の観客目線からむき出しにならないこと。
- アルミ調・ステンレス調・塗装パネルなどの落ち着いた素材と細い目地。エスカレーターの側板・周囲天井と整合させる。
- 下面に照明を追加するなら少数かつ自然に。強すぎる発光や過剰なドローコールを避ける。
- **プレイヤー・NPCが通行する場所の頭上クリアランス**、床開口、柱、非常口、店舗との干渉を検証する。危険または低すぎる部分は通れないよう建築的に処理する。
- 表示用パネルのCollisionと機械本体のCollisionを整理し、二重判定によるひっかかりやES動作への干渉を防ぐ。
- 各階ごとに「ES真下の見上げ」「斜め下45°」「側面」「上階踊り場」「乗降口」の撮影を必須とする。**上から見た画像だけで完成認定しない**。

## 4｜C館ドッグランを「芝生の上」に再配置【最重要】
現在の `source/v22/commons.json` には `C-DOG-RUN` と `C-DOG-TURF`、二重ゲート `C-DOG-outer` / `C-DOG-inner` がある。前バージョンの移設履歴もあるが、**草地として見えない・芝生の外に柵がある**というプレイヤーの指摘を優先して現物を修正する。

- まず**C館の屋外中庭に実際に存在する緑地**と、ドッグランの囲いの位置を上空・地上・外側・ゲート側から撮影・確認する。
- 使用可能な緑地があれば、柵とゲートを**その芝生エリアへ一体的に移動**させる。
- 使用可能な緑地が不足している場合は、既存中庭の景観・構造床・導線との整合を確認したうえで、明確に芝生と認識できる芝地を計画する。緑一色の薄板を既存舗装へ重ねるだけの対処は禁止。草地の質感、短い芝、適度な変化、見切り・縁石、地面の連続性をつくる。
- **柵内の主たる走行面は芝生**にする。舗装はゲート前の待機・通路など最小限の場所に限定。芝生の上に見えることを実画面で判断する。
- フェンスが芝生を一周して囲うよう整える。二重ゲートは「外部→前室→芝生内」になるよう機能させ、すり抜け・開けっぱなしにならない構成にする。
- 水飲み場、足洗い場、ゴミ箱、犬の排せつ物回収設備、ルール看板、ベンチ、日陰、遊具を必要範囲で置く。ただし走行空間を塞がない。
- 子供の遊び場、フードトラック、カフェ席、通路、外周道路、店舗入口を侵食しない。C館の開放感・屋外感を維持。
- 元の `C-DOG-TURF` を削除・再配置する場合は、旧位置の芝生・柵・当たり判定を残さず、**表示・衝突・地図・ルート・案内サイン**を同じ位置情報へ同期する。
- 旧 `dog-access.json` の約153m経路を正解として固定しない。新位置への自然な実在通路を検査し、階段・床・建物を突き抜ける近道は作らない。
- **緑色の板があること、座標が一致することだけで合格にしない**。地上から見て芝生で囲まれたドッグランであることを最優先にする。

## 5｜明確な完成基準
### B館
- 1F〜RFの新連続ESについて、各階で**上り・下り・乗り継ぎを実画面で確認**。
- 旧・新ESが同じ位置／同じ乗場機能で重複しない。
- EVホール・ES乗り場・通路が直感的に利用できる。
- エスカレーター底面が上階／下階どちらからも化粧仕上げ済み。機械・戻り踏段・突き出した裏面が露出しない。
- 転落・床抜け・頭上干渉・透明衝突壁なし。
- F6比較版と通常統合版の切替が維持される。比較版の変更を通常版へ誤混入しない。

### C館
- **芝生の上にドッグランが存在**することを、地上目線と鳥瞰の両方で判定。
- ダブルゲートの外から芝生内まで無理なく移動可能。
- 周辺のキッズ施設、フードトラック、共用回廊と干渉しない。
- C館構造別案F4で草地・柵・動線が破綻しない。
